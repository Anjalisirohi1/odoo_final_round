# Phase 6: Supervised Deal Prediction & Forecasting — Training Documentation

## 1. Supervised Learning Architecture

The Deal Prediction engine uses a supervised classification pipeline to estimate deal win/loss conversion probability, predict outcomes, calculate statistical confidence, forecast expected revenue, and prioritize deals.

```text
Raw Business Data (Quotations, Customers, Items, Orders, Events)
                           │
                           ▼
               Target & Feature Builders (Leakage-Safe)
                           │
                           ▼
               Stratified Train/Test Split (80/20)
                           │
                           ▼
          Scikit-Learn Preprocessing Pipeline (StandardScaler + OneHotEncoder)
                           │
            ┌──────────────┼──────────────┐
            ▼              ▼              ▼
    LogisticRegression RandomForest GradientBoosting
            │              │              │
            └──────────────┼──────────────┘
                           ▼
              Model Evaluator (ROC-AUC / F1)
                           │
                           ▼
              Optimal Model Selection & Persistence (Joblib + JSON Metadata)
```

---

## 2. Candidate Models Compared

1. **Logistic Regression**: Linear baseline with L2 regularization and balanced class weights.
2. **Random Forest Classifier**: Ensemble of 100 decision trees (max depth 6) with balanced weights.
3. **Gradient Boosting Classifier**: Sequential boosting ensemble (100 estimators, learning rate 0.1, max depth 3).

---

## 3. Evaluation Metrics

Models are evaluated on an independent, stratified holdout test split ($20\%$ of samples) across:
- **ROC-AUC**: Primary selection metric for threshold-invariant ranking performance.
- **F1 Score**: Harmonic mean of precision and recall.
- **Accuracy**: Overall classification accuracy.
- **Precision**: Proportion of predicted conversions that converted.
- **Recall**: Proportion of actual conversions identified.
- **Confusion Matrix**: Full breakdown of true positives, false positives, true negatives, and false negatives.

---

## 4. Model Persistence & Artifacts

All production artifacts are serialized to `artifacts/prediction/`:
- `best_model.joblib`: Serialized tuple of the trained model, fitted `PredictionPreprocessor`, feature names, and model identifier.
- `metadata.json`: Model version, training timestamp, sample counts, class distributions, and test evaluation metrics.
- `evaluation.json`: Complete comparison matrix across all candidate models.

## 5. Offline Training vs. Online Serving Lifecycles

### Offline Training Lifecycle (Explicit CLI)
- Executed via: `python scripts/train_prediction_model.py`
- Responsibilities:
  1. Loads/generates training quotations and historical business entities.
  2. Constructs leakage-safe features and binary conversion labels.
  3. Executes stratified train/test split.
  4. Trains and cross-evaluates candidate models (`LogisticRegression`, `RandomForest`, `GradientBoosting`).
  5. Selects the optimal model based on ROC-AUC.
  6. Persists artifacts to `artifacts/prediction/` (`best_model.joblib`, `metadata.json`, `evaluation.json`).

### Online Serving Lifecycle (FastAPI Application)
- Executed via: `uvicorn src.main:app`
- Responsibilities:
  1. On application startup, checks if `artifacts/prediction/best_model.joblib` exists.
  2. If present: deserializes the pipeline and initializes `DealPredictionService` for low-latency inference.
  3. If missing: does **not** train automatically and does **not** block application startup. Instead, marks `is_initialized = False` and returns HTTP 503 (`MODEL_NOT_TRAINED`) upon prediction requests.

---

## 6. Synthetic Data Limitations

The current model is trained and validated on synthetic B2B enterprise deal distributions generated by `SyntheticDataProvider` (`seed=42`). In production deployment:
1. Model weights should be retrained on real enterprise CRM and PostgreSQL quotation history.
2. Continuous performance monitoring (concept drift & covariate shift) should be scheduled periodically.
